Cloudflare Pages

Start with the basics. Cloudflare Pages is a free static hosting platform with a global CDN and preview deploys for every pull request.

In practice that means: Connect a Git repo and every branch or PR gets its own preview URL, while the main branch gets a production URL on Cloudflare's network. The free tier covers static sites comfortably and custom domains are supported without a separate CDN bill.

No signup wall, no credit card — just a README and some patience.

  • Create a Pages project in the Cloudflare dashboard and link the repo
  • Point the build output at the static folder
  • Add a custom domain in the project's domains tab

Github Pages

Start with the basics. GitHub Pages is a free static-hosting service built directly into the repo that already hosts your code.

The upshot: Point Pages at any subdirectory of a repository and GitHub serves it over HTTPS with a built-in URL, custom domain support, and automatic deploys on every push. For a static blog the entire hosting bill is zero, with no server, no DNS glue, and no renewal dates.

If you only do one thing today, make it this one.

  • Pick a directory (e.g. autopilot-blog/site/) as the site source in repo Settings → Pages
  • Push (or let the engine push) the built HTML and the site deploys in under a minute
  • Optionally map a custom domain in the same settings page

Is-a.dev Free Domains

Worth spending ten minutes on: is-a.dev gives you a real custom domain — username.is-a.dev — completely free, pointed at your GitHub Pages site.

In other words: It is the fastest path from user.github.io/repo to a name that looks like an actual domain. You request the subdomain, add a CNAME record, and the platform handles the certificate. There is no invoice, ever.

No signup wall, no credit card — just a README and some patience.

  • Request yourhandle.is-a.dev in the is-a.dev app
  • Add the provided CNAME record to your repo's Pages settings
  • Wait a few minutes for propagation
