Free Custom Domain Email Hosting on a $0 Budget: An Honest Walkthrough

Let's be honest: the internet is full of posts that pretend free custom domain email hosting is complicated. It isn't. What's actually complicated is separating the free options that hold up from the free options that quietly become $20/month. That's what this post digs into.

We'll walk through Is-a.dev Free Domains, Github Pages, Cloudflare Pages, and Automate the boring parts — and finish with the questions people actually ask, so you can check before you buy anything. You shouldn't have to buy anything.

Is-a.dev Free Domains

First, the thing that actually matters: is-a.dev gives you a real custom domain — username.is-a.dev — completely free, pointed at your GitHub Pages site.

So what does that look like when you're actually doing it? It is the fastest path from user.github.io/repo to a name that looks like an actual domain. You request the subdomain, add a CNAME record, and the platform handles the certificate. There is no invoice, ever.

For a personal project or side business, this covers you without breaking a sweat.

  • Request yourhandle.is-a.dev in the is-a.dev app
  • Add the provided CNAME record to your repo's Pages settings
  • Wait a few minutes for propagation

Github Pages

The short version: GitHub Pages is a free static-hosting service built directly into the repo that already hosts your code.

In practice that means: Point Pages at any subdirectory of a repository and GitHub serves it over HTTPS with a built-in URL, custom domain support, and automatic deploys on every push. For a static blog the entire hosting bill is zero, with no server, no DNS glue, and no renewal dates.

Write down what you change and why — your future self will thank you.

  • Pick a directory (e.g. autopilot-blog/site/) as the site source in repo Settings → Pages
  • Push (or let the engine push) the built HTML and the site deploys in under a minute
  • Optionally map a custom domain in the same settings page

Cloudflare Pages

First, the thing that actually matters: Cloudflare Pages is a free static hosting platform with a global CDN and preview deploys for every pull request.

Concretely: Connect a Git repo and every branch or PR gets its own preview URL, while the main branch gets a production URL on Cloudflare's network. The free tier covers static sites comfortably and custom domains are supported without a separate CDN bill.

Keep it this simple and you'll be ahead of most tutorials out there.

  • Create a Pages project in the Cloudflare dashboard and link the repo
  • Point the build output at the static folder
  • Add a custom domain in the project's domains tab

Automate the boring parts

First, the thing that actually matters: Anything you do twice by hand should become a script. That's the entire discipline of free automation.

The upshot: A cron expression, a webhook, or a scheduled workflow costs nothing to run and buys back an hour every week. Start with one small automation — a nightly backup, a feed check, a deploy on push — and add more only when the first one proves itself.
